# Implementation map

The source uses the standard library for the supervisor, state, approval broker,
CLI, platform integration and tests. Live packages are imported only in the live
adapters. No work is triggered at import time.

| Subsystem | Responsibility |
|---|---|
| `config`, `security`, `store` | Typed configuration, DPAPI/ACLs, SQLite state, retention and recovery |
| `approvals`, `verification` | Exact content and exact command approval; deterministic application |
| `codex`, `supervisor` | Stdio JSON-RPC, account/permission checks, coding/review/conversation turns, selected chats |
| `calls`, `audio` | Deterministic call policy, streaming resampling, bounded playback and local VAD |
| `voice` | Gemini streaming audio/tools and local whisper.cpp/Piper processes |
| `transport` | Isolated Telegram login session, owner-only messages, native PCM and call lifecycle |
| `service` | Orchestration, owner commands, quotas/fallback, heartbeat and inbox |
| `platform`, `cli` | Local single-instance lock, tray, startup XML and operator controls |

## Task flow

1. The owner submits a task or hands over an idle selected chat.
2. A restricted Codex worker inspects files and returns a structured report.
3. Questions become blockers; proposed changes receive independent read-only review.
4. A favorable review creates a content-bound proposal for owner review. Unfavorable
   review becomes a blocker rather than looping through unbounded model corrections.
5. The owner approves the exact digest or rejects it. No project edits precede approval.
6. Application reads back content and leaves verification explicitly pending.
7. A separate approved verification command records its actual exit code and output.

Worker capacity rejects excess starts without launching more processes. Tasks remain
visible for explicit `/run` after capacity becomes available. The conversation has
its own serialized reasoning thread; coding results never block audio capture.

## Call flow

The supervisor persists a call reservation before instructing the child process.
The child verifies the sole peer and establishes media. The voice provider starts
only after a connected event. Incoming audio remains active during playback.
Interruption clears queued output. Call timeout/transport failure ends media without
cancelling coding work or scheduling a retry.

Automatic calls consume unresolved, sufficiently old blockers transactionally and
coalesce them into a single call context. Restart never replays an attempted blocker.
Quiet hours and frequency limits apply to automatic calls; direct requests can
override quiet hours. Both paths share the one-call-at-a-time gate.

## Local command channel

The local CLI writes an inbox command into the owner-protected SQLite database.
The service claims it once and writes its result. An interrupted in-flight command
becomes uncertain after restart. There is no public listening port or network API.

## Compatibility boundaries

Codex protocol shapes were checked against schemas generated by installed version
`0.167.0-alpha.3.2`. Runtime capability checks still govern future versions.
The dependency locks target CPython 3.12 on Windows x64. The metadata resolver is
bounded, deterministic and fails conflicts instead of acting as a general-purpose
backtracking package manager. Installation still needs `pip check` and import probes.
